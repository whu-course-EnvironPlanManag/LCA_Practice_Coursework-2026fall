# A前期数据：IDE交接包

主文件是 `a_phase1_ide_handoff.json`。把这一个文件交给IDE即可；它内置数据字典、原始资料、来源、推荐前端代理、备选工艺、未解决参数以及建模指令。读取使用UTF-8。

本次将两轮已交付资料合并，不运行模型，不修改上传原件，也不把缺失值填成0。年度规模8万t和60/40属于仿真规划设定。原型的15万能力、2024年10万回收量、2026年30万折算设计规模仍保留为不同边界的背景事实，不替代规划进料。

建议IDE依次读取 `conventions → case_definition → baseline_inputs → calculation_gates`。`baseline_inputs`明确选择JR23整包/电芯的同源前端组成；`candidate_process_parameters`全部未启用。完整原始记录在`evidence_register`，仅供追溯，不应直接批量当模型输入。

## 现在可以开始

- 数据加载、字段/来源/单位校验。
- 8万t/a规划收到来料的LFP/混合三元质量分配。
- 以推荐整包及电芯组成核算收到来料的组分存量，明确名称为“来料构成估算”。
- 搭建预处理、Li物质流、工程规模的接口与方程；为null输入输出明确缺失原因。

## 仍需补定才能形成正式结果

SOH分流比例、实际粉料捕集效率、粉料干湿基、非黑粉Li去向、工序Li分配、湿法模块兼容关系、酸量版本、能源水量和运行时数等在`unresolved_inputs`逐项列出。B的因子选择以及C的价格/CAPEX/OPEX/政策另列为外部必需输入。`calculation_gates`按模块依赖继承上游缺参，避免只填局部值就误报全结果就绪。完整MFA、Li守恒验收、小时设备规模、完整LCA/TEA当前均为not-ready。没有预设全部8万t都送去回收。

组成代理的比例已统一为0–1；原始百分数保留作对照。整包/电芯的完整分配可检查和为1；黑粉部分元素清单不能归一化，PO4不是P。药剂浓度不是纯物质用量，kgce不是kWh，区域CO2因子不是生命周期CO2e因子。

同源黑粉Li含量和组成留作参照，不能直接将朗赛酸耗接到金瑞黑粉。混合三元代理没有被证实等于NMC622或811。原gas表单位歧义和两版酸量均已显式隔离。

## 可直接粘贴给IDE的任务

请读取随附JSON的`ide_bootstrap_instructions`并据此开始A成员中期代码。先构建数据加载/校验、来料构成及预处理/Li流股接口；按`calculation_gates`区分可计算模块与待补模块。候选参数不自动启用，null不得填0，未就绪完整Li衡算不得输出PASS。将mfa_model.py与engineering_plan.py分开，保留与B的LCA、C的TEA/政策接口，不擅自改成已有工厂实测研究。

后续选用备选工艺或增添工程假设时，另写选择/覆盖配置并说明来源、理由及不确定性，保留此交接文件为只读快照。

附带的`.schema.json`可供IDE进行JSON Schema校验；主JSON本身不依赖该文件才能读取。`数据交接校验结果.json`只表示数据结构/来源/单位合同校验通过，不表示科学模型或Li衡算已通过。
