## 运行顺序

在本目录执行，Python 3.10以上：

```powershell
python -m pip install -r code_implementation/requirements.txt
python code_implementation/run_analysis.py --extract-yearbook
python code_implementation/run_analysis.py --plot-yearbook
python code_implementation/run_analysis.py --check-inputs
python code_implementation/run_analysis.py --self-test
```

组员按[data_cohort/README_data_sources.md](data_cohort/README_data_sources.md)填好相应输入后：

```powershell
# 只具备物质流数据时，先核算dMFA和元素守恒，不需要等报价或LCA清单齐全
python code_implementation/run_analysis.py --dmfa-only

# 全部模块输入完整后，一次生成情景、锚点、网络、项目表和图形
python code_implementation/run_analysis.py --run
```

无参数运行会显示帮助。从仓库根目录也可通过完整脚本路径运行，模型定位不依赖当前工作目录。运行不联网，不自动执行Git add、commit或push。

`--plot-yearbook`无需安装队列或工艺参数，在`figures_output/`生成三张真实背景图，仅保存PNG（300 DPI），并更新`data_readiness.json`和`待补数据清单.md`。原值和出处统一保留在`data_cohort/`，不再重复输出来源CSV、PDF/SVG或检查文件。背景图展示各类燃料私人汽车存量、省级电力生产/消费和原表12城市电量，不能当成电池预测、绿电比例或选址结论。模型图仍须待完整输入后运行`--run`。

## 模型定义和不能混用的口径

### 1. 年度安装队列与退役概率

安装量输入单位为kWh，必须包括研究边界内需要核算的替换电池。年末安装，当年不退役；在服役第a年：

```text
S(a) = exp[-(a/eta)^beta]
P(a) = S(a-1) - S(a),  a >= 1
退役量(t) = sum_vintage 安装量(vintage) × P(t-vintage)
在用量(t) = sum_vintage 安装量(vintage) × S(t-vintage)
```

年度概率使用CDF差分，不用Weibull密度在整数年龄上的点值；预测期末的生存尾部保留在库存中。eta是尺度参数，不直接等于平均寿命。材料含量、整包比能量及寿命参数按原安装年份锁定，不能用2030年的参数追溯改写2015年的电池。

提供的是车辆保有量时，不能直接差分得到电池安装量。须另有分车型/BEV-PHEV结构、单车容量、换电与更换、跨省迁移等证据。`stock_driven_installations()`只对给定的**电池容量目标存量**反推安装量；遇到目标下降快于自然退役时拒绝负安装量，需要另建提前退役机制。

完整历史安装队列与期初存量可二选一。同一城市/体系不能重复计入。期初年龄队列采用条件生存率`S(age+k)/S(age)`，不能让已经生存多年的电池重新获得一段全新寿命。

### 2. 锂及伴生金属、正规收集与梯次库存

元素质量由安装kWh乘以该队列的kg元素/kWh计算；整包质量由kWh除以整包比能量计算。输入至少包括Li，当前同时核算Ni、Co、Mn，没有足够材料组成时不声称完成全电池所有元素守恒。

```text
当年首次退役 = 正规收集 + 正规系统外去向
正规收集 = 当年直接精炼 + 梯次入库
当年精炼进料 = 直接精炼 + 往年梯次到期释放
精炼元素进料 = 再生产品中的元素 + 未回收残余中的元素
期初在用 + 新安装 + 期初梯次库存
  = 期末在用 + 期末梯次库存 + 再生产品 + 未回收残余 + 正规系统外去向
```

每年、每城市、每体系、每元素输出独立收支，误差须严格小于0.05%。残余项是输入的有效回收率所定义的未回收元素，不指定为实测废水或尾渣；正规系统外去向也不直接称为环境排放。

梯次模块是**有来源的整数年滞后队列**，不是SOH衰减曲线优化。明确假定元素在梯次阶段不流失、到期返回正规体系；当前空间接口要求明确批准“返回原城市”的简化情景。若有跨城流转、部件更换或梯次残余损失，应扩展相应OD和元素流。代码不伪造梯次初始库存：必须确认起算前为零，或从更早完整历史起算。

### 3. 政策与收益

`policy_rules.json`是阈值唯一来源。引擎区分湿法/火法与材料修复，区分含有与不含有的金属，严格处理`<2200`及杂质`<1.5%`。EU回收目标的截止日和再生含量的起始日分别处理，不能提前整年套用。

输出`Redline_Vetoed`表示未满足**已配置的课程筛选条件**；`Data_Incomplete`表示必要数据缺失；其他状态仅为数值检查通过。正式2024行业规范具有引导性，不能将它的全部条件说成行政审批前置要求。法规范围、2026管理办法及项目实际许可仍由负责政策的组员审核。未提供全部碳阈值和整电池证据时，不宣称已获EU认证。

碳收益只有显式配置`scenario_credit`且确认权益/适用性时才计算；出口溢价只有合同情景配置时才计算。水资源税使用工厂直接取水量，不能用包含上游发电的生命周期水耗替代。环保税使用有明确单位的应税量，治理费用另列LCI，避免重复。

### 4. LCA、经济性与功能单位

过程LCI统一为**每吨进入精炼环节的退役整包电池**，运输为吨·公里；报价统一CNY。各路线需显式列出电力、预处理、热能、试剂、污染控制，即便确认为零也要有证据。

主比较仅对实际产出电池级碳酸锂的路线提供**每吨LCE产品**的结果。含锂元素质量与LCE的换算仅为化学计量：

```text
Li转LCE系数 = M(Li2CO3)/(2M(Li)) ≈ 5.323
LCE产量 = 实际再生Li质量 × Li转LCE系数
```

该换算不把混合金属盐或直接修复正极变成真实的碳酸锂产品。`direct`可用于政策模块测试和工艺筛选，但**本版完整LCE比较会拒绝把直接修复正极套用碳酸锂售价/原生LCE基准**；若研究直接修复的经济排序，应另补同功能正极材料或服务基准后扩展，不能用论文摘要数字填表。

电力碳、水、价格三类因子随绿电比例分别混合。环境负荷需要有出处的Li产品分配方法；全系统其他产品收入不能自动换成同等环境信用。盐湖卤水和锂辉石必须分别提供同边界、同功能单位的原生基准，再分别计算前沿。

```text
CRF = i(1+i)^n / [(1+i)^n-1]，i=0时取1/n
LCOR = (年化资本 + OPEX + 采购 + 物流 + 政策修正 - 副产品/服务收入) / LCE产量
年净成本 = 上述成本 - 主产品LCE销售收入
MAC = (再生LCOR - 原生同口径生产成本) / (原生GWP - 再生GWP)，分母换算为吨CO2e
```

LCOR不先减去主产品LCE销售收入；否则不能直接与原生生产成本比较。无正向减排时MAC输出空值，不伪造零成本或负成本减排。收购成本按有出处的“化学体系—LCE价格—SOH”报价表查找，不自建未经校准的价格弹性；有新价格情景时要同步补报价。

### 5. 空间网络与500组情景

城市为供给起点，候选地类型包括收集中心、梯次中心和精炼基地。允许“城市→收集→精炼”和“城市→收集→梯次”两类边；往年梯次返厂量来自dMFA，不把当年梯次入库立即计为精炼原料。仅使用有出处的道路距离，直线示意图不参与运距核算。

MILP最小化运输、节点运行和年化固定费用，满足起点/收集节点守恒、候选地资格与吞吐量上限。每个工况的工程CAPEX为实际选中节点的CAPEX之和，不重复叠加一笔区域资本年金。精炼和梯次节点的变动费用分别在LCI/服务模型计取，网络相应字段须为零以免重复。网络中的建站固定成本计入一次。

默认20档正规收集率×25档绿电份额是**研究设计情景**，不是湖北统计事实。价格与工艺可增加独立维度。程序保留政策/数据/网络不可用的工况及原因，不用负流量截断或假点填前沿。

帕累托严格要求“所有目标不劣、至少一项更优”。相同目标的不同物理方案保留；目标范围为零时归一化该维为零。A最低LCOR，B归一化理想点欧氏距离最小，C最低GWP。B只是规则选出的代表点，退化时不宣称识别出了唯一内部折中拐点。

**寻优范围限制：**网络先按费用最小求解，外层遍历收集率、绿电、价格与已提供工艺，所以结果是该顺序模型的条件前沿，不是枚举所有可能空间网络后的连续全局多目标最优。
